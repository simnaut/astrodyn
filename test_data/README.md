# Test Data

Reference data for Tier 2 and Tier 3 cross-validation tests.  JEOD reference
data is used **only** for comparison — never as input to our computation.

## Files

### JPL Ephemeris

| File | Size | Source |
|------|------|--------|
| `de421.bsp` | 16.8 MB | JPL Development Ephemeris 421 (SPICE binary) |
| `de405.bsp` | 63 MB | JPL Development Ephemeris 405 (SPICE binary, byte-swapped) |

#### DE421 (production ephemeris)

```bash
curl -Lo test_data/de421.bsp https://public-data.nyxspace.com/anise/de421.bsp
```

Standard NASA/JPL product covering 1899-2053. Used as the production ephemeris
for all non-cross-validation scenarios.

**Used by:** `astrodyn_ephemeris/tests/ephemeris_validation.rs`, all Tier 3
trajectory tests except Apollo 8 frame switch.

#### DE405 (cross-validation only)

**Do not use DE405 for anything other than JEOD cross-validation.** JEOD v5.4
defaults to DE405 via compiled C++ Chebyshev coefficient arrays. To match JEOD's
ephemeris exactly, the Apollo 8 frame switch test uses DE405. For all other
purposes, use DE421 (more accurate, based on additional decades of observations).

**How the file was made:** JPL distributes DE405 only in the pre-2003 big-endian
DAF format, which ANISE cannot read (it requires the `LTL-IEEE` / `BIG-IEEE`
endian flag added to DAF in 2003). The committed `de405.bsp` was converted from
big-endian to little-endian with a Python script that:

1. Downloaded the original from `ftp://ssd.jpl.nasa.gov/pub/eph/planets/bsp/de405.bsp`
2. Swapped the file record integers and endian flag to little-endian
3. Swapped each summary record (epoch doubles + body/frame integers)
4. Swapped all data records (Chebyshev coefficient doubles)
5. Preserved ASCII fields (internal name, comment area, segment names)

The conversion preserves all numerical data at full f64 precision. The resulting
file passes ANISE's DAF validation and produces ephemeris states consistent with
JPL Horizons to sub-millimeter precision.

**Used by:** `astrodyn_runner/tests/tier3_apollo8_frame_switch.rs` only.

### JEOD SIM_dyncomp Trajectories

These CSV files contain ISS translational state (position, velocity) at 60-second
intervals over an 8-hour propagation, generated by JEOD's `verif/SIM_dyncomp`
verification sim running inside a Rocky Linux 9 container with Trick 25 and
JEOD 5.4.

| File | JEOD Run | Gravity model | Used by |
|------|----------|---------------|---------|
| `dyncomp_run2_state.csv` | RUN_2 | Spherical (point-mass) | `astrodyn_runner/tests/tier3_sim_dyncomp_run2.rs` |
| `dyncomp_run3a_state.csv` | RUN_3A | 4x4 spherical harmonics (GGM02C) | `astrodyn_runner/tests/tier3_sim_dyncomp_run3.rs` |
| `dyncomp_run3b_state.csv` | RUN_3B | 8x8 spherical harmonics (GGM02C) | `astrodyn_runner/tests/tier3_sim_dyncomp_run3.rs` |

Additional files generated but not currently consumed by tests:

| File | Contents |
|------|----------|
| `dyncomp_run*_Earth_RNP.csv` | Earth rotation/nutation/precession state (archived for future RNP validation) |
| `dyncomp_run*_rnp.csv` | Same as above (alternate naming from older generation runs) |

**CSV column layout** (comma-separated, 1 header line):

```
Column  0: sys.exec.out.time {s}
Column  1: composite_body.state.trans.position[0] {m}
Column  2: composite_body.state.trans.velocity[0] {m/s}
         (columns 3-7: rotation matrix row 0, quaternion scalar, angular velocity x)
Column  8: composite_body.state.trans.position[1] {m}
Column  9: composite_body.state.trans.velocity[1] {m/s}
         (columns 10-14: rotation matrix row 1, quaternion y, angular velocity y)
Column 15: composite_body.state.trans.position[2] {m}
Column 16: composite_body.state.trans.velocity[2] {m/s}
         (columns 17-21: rotation matrix row 2, quaternion z+w, angular velocity z)
```

**Sim configuration** (common to all runs):

- Epoch: 2007-11-20 00:00:00 UTC
- Duration: 28,800 seconds (8 hours), logged every 60 seconds (481 data points)
- Vehicle: ISS mass configuration
- Integrator: RK4 (JEOD's er7_utils)
- Integration frame: Earth-centered inertial (J2000)
- Atmosphere: enabled (MET model), aerodynamic drag: OFF

## How to Reproduce (Docker)

The JEOD trajectory data is generated by running JEOD verification sims inside a
Docker container.  Prerequisites: `../trick` (Trick 25 checkout) and `../jeod`
(JEOD 5.4 checkout) as sibling directories.

```bash
# 1. Build the container (context is parent dir so trick/ and jeod/ are accessible)
docker build -f trick/Dockerfile -t jeod-trick ..

# 2. Generate reference data into test_data/
mkdir -p test_data
docker run --rm -v $(pwd)/test_data:/output jeod-trick
```

The container runs `trick/generate_references.sh`, which:

1. Builds each JEOD verification sim with `trick-CP` (Trick's S_define compiler)
2. Runs the sim from the **SIM root directory** (not `SET_test/RUN_*/`), because
   JEOD's `input.py` files use paths relative to the SIM root
3. Collects ASCII CSV output files, canonicalizing names (e.g.,
   `log_state_ASCII.csv` becomes `dyncomp_run2_state.csv`)
4. Copies binary `.trk` files for archival (these are gitignored)

|-------|----------|----------|---------|
| `dyncomp_run2` | `verif/SIM_dyncomp` | `SET_test/RUN_2` | Point-mass gravity baseline |
| `dyncomp_run3a` | `verif/SIM_dyncomp` | `SET_test/RUN_3A` | 4x4 harmonics gravity |

`dyncomp_run2` is required (script exits on failure); all others are optional
(`|| true`).

### Moon Orientation (DE421 Libration)

| File | Size | Source |
|------|------|--------|
| `moon_pa_de421_1900-2050.bpc` | 1.7 MB | NAIF Binary PCK — DE421 lunar principal axes |

Contains Chebyshev coefficients for the Moon's body-fixed orientation (frame
31006) derived from the same DE421 data that JEOD uses internally. Loaded via
`Ephemeris::load_bpc()` to enable high-fidelity Moon rotation for spherical
harmonics gravity evaluation.

**How obtained:**

```bash
wget -O test_data/moon_pa_de421_1900-2050.bpc \
  https://naif.jpl.nasa.gov/pub/naif/generic_kernels/pck/moon_pa_de421_1900-2050.bpc
```

**Used by:** `crates/astrodyn/tests/tier3_sim_earth_moon.rs` (Clementine lunar orbit,
LP150Q 60x60 gravity + cannonball SRP, dt=0.03125s — achieves 0.93 m parity over 7 days)

### Mercury Relativistic Reference Data (not committed)

| File | Size | Source |
|------|------|--------|
| `mercury_newtonian_mercury.csv` | ~774 MB | SIM_mercury RUN_newtonian |
| `mercury_relativistic_mercury.csv` | ~774 MB | SIM_mercury RUN_relativistic_sun |

These files are **gitignored** because they are ~774 MB each (5.2 million rows
covering a 600-year Mercury propagation at 1-hour intervals from epoch
1600-01-01 TDB). They validate the post-Newtonian relativistic gravity
correction by comparing Newtonian vs GR-corrected trajectories.

**How to generate:**

```bash
# Requires the jeod-trick Docker image (see "How to Reproduce" section above)
docker run --rm \
  -v $(pwd)/test_data:/output \
  -v $(pwd)/trick/generate_references.sh:/generate_references.sh:ro \
  --entrypoint /bin/bash \
  jeod-trick /generate_references.sh
```

The script's SIM_mercury group (Group 28) runs two configurations:
- `RUN_newtonian`: pure Newtonian gravity with 9 planets (Sun + 8 planets)
- `RUN_relativistic_sun`: same setup with post-Newtonian correction enabled
  for the Sun's gravitational field

**CSV column layout** (interleaved):

```
Column 0: sys.exec.out.time {s}
Column 1: position[0] {m}
Column 2: velocity[0] {m/s}
Column 3: position[1] {m}
Column 4: velocity[1] {m/s}
Column 5: position[2] {m}
Column 6: velocity[2] {m/s}
```

**Used by:** `crates/astrodyn/tests/tier3_sim_mercury.rs` — validates that the
relativistic correction produces a measurable trajectory divergence. The full
perihelion advance measurement (~43 arcsec/century) requires propagating both
trajectories and measuring the argument of periapsis drift over multiple
Mercury orbits.

## Gitignore Policy

Binary `.trk` files (Trick's native log format) and Mercury reference CSVs
(~774 MB each) are gitignored. All other CSV, `.bsp`, and `.bpc` files are
committed. The gitignored files can be regenerated from the Docker container.
